# Switch Inspector Next

Switch Inspector Next 是一个面向 Windows 桌面环境的交换机巡检工具，支持通过 SSH 或 Telnet 巡检华为 VRP 和 H3C Comware 设备。

## 功能

- 管理交换机资产，支持 Excel 导入、模板下载，以及 CIDR / 地址范围批量添加。
- 无需选择连接协议，优先 SSH，连接或登录失败后自动在同一个端口尝试 Telnet。
- SSH 登录后先执行 `display version`，根据设备实际返回内容识别华为或 H3C 平台。
- 根据识别到的平台设置分页方式，再执行巡检命令。
- 在设置页分别维护华为和 H3C 命令清单，支持新增、编辑、排序、启停和恢复默认命令。
- 每次巡检开始前展示本次启用的命令，人工确认后才连接设备。
- 每个并发线程提供一个实时命令窗口，显示当前设备、命令和输出。
- 并发数限制为 1–16，默认 5；取消任务后已建立的 SSH 会话会正常结束。
- 可选采集设备 SN。SN 采集失败只记录为未识别，不影响其他巡检结果。
- 资产列表支持搜索和筛选，筛选结果一次显示，不做分页。
- 温度、端口、当前告警、最近日志及入向/出向累计错包分析，清晰区分缺失值与真实零值。
- 应用内报告与离线 HTML 使用相同分析：顶部图表、简版汇总表、下方折叠详情；可按任务、关键词、状态、分组查看。
- 巡检结果、设备详情和报告归档保存在本机，保留 HTML、JSON 与逐设备配置文本。

## 运行要求

- Windows 10 或更高版本
- Python 3.10 或更高版本（从源码运行时）
- Microsoft Edge WebView2 Runtime

WebView2 是桌面界面运行所需的系统组件。打包后的 EXE 不包含 WebView2，其他 Windows 电脑首次运行前需要安装它。

## 从源码运行

```powershell
python -m pip install -r requirements.txt
python main.py
```

启动演示工作区：

```powershell
python main.py --demo
```

演示工作区只使用示例数据，不会连接真实设备。

## 构建 EXE

在 Windows PowerShell 中执行：

```powershell
.\build.bat
```

输出文件为：

```text
dist\SwitchInspectorNext.exe
```

EXE 使用 PyInstaller 的单文件、无控制台模式构建，运行时仍需要系统 WebView2 Runtime。构建脚本已排除 Qt、CEF、Tk 等未使用模块，以减少体积。

## 测试

运行后端和单元测试：

```powershell
python -m pytest tests --ignore=tests/test_ui.py -q
```

运行浏览器端 UI 测试需要安装 Playwright 并启动静态文件服务：

```powershell
python -m pip install playwright
python -m playwright install chromium
python -m http.server 8767 --directory ui
```

保持服务运行，在另一个终端执行：

```powershell
python tests/test_ui.py
```

UI 测试使用演示数据，覆盖资产搜索、筛选、命令确认、并发控制台、任务取消与完成、报告页面和空工作区。

## 数据位置

应用数据默认保存在：

```text
%LOCALAPPDATA%\SwitchInspectorNext
```

设备凭据由 Windows DPAPI 加密保存。命令清单按华为和 H3C 平台分别保存。

## 采集说明

设备保持在用户视图中，应用不会自动进入配置模式或提权。默认分页命令为：

- 华为：`screen-length 0 temporary`
- H3C：`screen-length disable`

不同型号或版本可能存在命令差异，建议在设置页按现场设备实际情况人工核对和调整命令清单。

### 华为模拟器 Console 分页

部分 S5700/VRP 5.x 通过 Console 连接时，`screen-length 0 temporary` 会返回 `Error: The type of the included user interface must be VTY.`。这表示当前不是 VTY 会话，并非登录失败。

仅遇到这条明确错误时，应用会保留当前用户视图，自动响应输出末尾的分页提示并继续采集，不进入 `system-view` 或 `user-interface` 修改配置。日志和结果会注明自动翻页；归档会保留分页设置的原始错误，并从后续配置正文中去掉分页提示及终端控制字符。

每条命令仍受超时、5 MB 接收输出及最多 512 次翻页限制；缺少最终用户视图提示符、其他分页设置错误或超过限制时停止该设备采集，避免把不完整配置当成成功结果。

## SSH 连接排查

软件优先通过 SSH2 连接，使用账户密码认证；连接或登录失败后自动尝试 Telnet。请在 CRT 的会话属性中核对协议、地址、端口和认证方式。

- **连接端口**：SSH 与 Telnet 都使用资产里填写的同一端口，不会自动改为 23。新建设备默认端口为 22；Telnet 服务在 23 时填写 23，模拟器服务在 2000 时填写 2000。Excel 继续兼容原有的“SSH端口”表头，该列现同时用于 Telnet 回退。
- **模拟器控制台**：`127.0.0.1:2000` 等地址可能是模拟器的 Console/Telnet 服务。SSH 协议检查失败后会重新连接该端口尝试 Telnet，可识别用户名/密码提示，或已登录的 `<设备名>` 用户视图。回环地址指运行软件的当前电脑，在其他电脑上不会指向同一个模拟器。
- **设备出现握手乱码或算法列表**：通常表示 SSH 数据被控制台当作命令输入。软件在发送 SSH 握手前检查服务标识，发现控制台或 Telnet 提示会停止连接。
- **认证失败**：核对账户、密码及设备允许的登录方式；CRT 保存的公钥、代理或交互式认证与软件的密码认证可能不同。
- **算法不兼容**：老版本 VRP/Comware 与 CRT、Paramiko 可能存在协商差异。日志会区分密钥交换、主机密钥、加密及消息校验算法类别；应根据实际错误检查固件与设备算法配置。
- **终端建立失败**：核对账户的 SSH 交互终端权限、设备会话数及 SSH 日志。

Telnet 使用明文传输，回退时复用资产中保存的用户名和密码。新建设备无需选择 SSH 或 Telnet；任务日志、实时窗口和归档结果会记录回退及实际协议。只有连接或登录阶段失败才回退，版本无法识别、视图不安全、分页失败或其他巡检命令失败不会触发重新登录。

连接错误会标明失败阶段，且不在实时事件或结果中显示认证异常的原始文本，以避免泄露账户或密码。诊断信息不能替代具体型号、固件及设备 SSH 日志的核对。


## 按网段 / 地址范围添加

在“添加设备”中切换到“网段 / 地址范围”，每次填写一个表达式：

| 格式 | 示例 | 规则 |
| --- | --- | --- |
| CIDR | `192.168.1.0/24` | 按原规则取可用主机；/31、/32 保留全部地址 |
| 简写范围 | `192.168.1.1-10` | 同一网段的 .1 至 .10，包含两端 |
| 完整范围 | `192.168.1.254 - 192.168.2.10` | 可跨网段，包含两端，不排除 .0 或 .255 |

单次最多 4096 个地址，倒序、非法地址和超限范围会在展开前被拒绝；已有 IP 自动跳过。该批设备共用填写的厂商、端口、用户名、密码和分组。仍先使用 SSH，登录失败再在填写的同一端口尝试 Telnet。

## 分析命令与报告

新安装默认包含温度、端口、告警、日志和错包命令。已有命令清单不会自动覆盖：在设置页点击各平台的“补充分析命令”，只将缺少的命令追加到当前编辑区，保留原有顺序、内容和启停状态，人工核对后点击保存。每次巡检前仍需确认启用命令。普通命令不支持时记录单项问题并继续；连接中断、视图不安全、分页失败或超过安全上限时停止该设备。

- CPU / 内存：80% 提醒，90% 严重。
- 温度：60℃ 提醒，75℃ 或传感器明确异常时严重。
- 风扇 / 电源异常、活跃告警、警告及以上日志、非零错包分别列出。
- 端口 Up、管理关闭、链路 Down 只作统计；Down 不直接告警。
- 错包为设备累计值；日志只表示本次命令读取范围，不能据此推断变化趋势。
- 缺失数据区分“未采集”“设备不支持”“未识别”，不作为零值。已确认异常优先于指标缺失；SN 关闭、Telnet 回退和 Console 自动翻页不影响设备健康结论。

“报告与归档”默认展示最近任务，可切换历史。图表只分析所选任务，已删除资产的历史设备仍可查看。汇总表设备名称可定位并展开下方详情；应用内原始输出按需加载。旧归档使用已有结构化数据或重新解析原始输出，不修改旧文件。离线 HTML 内嵌样式、图表和交互脚本，不依赖网络或外部字体。

验证使用离线 CLI 样例、本地 SSH/Telnet 模拟服务及浏览器；真实型号和固件的命令兼容性仍需现场复测。
